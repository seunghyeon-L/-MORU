## 0. 이 설문이 답해야 하는 단 하나의 질문

> ⭐ **실사용자가 챌린지를 완주할 의향과 능력이 있는가?**

이게 이 프로젝트 **최대의 미검증 가정**이다 (→ `spec-02-design-updates.md` §10). 챌린지 완주율이 낮으면 차별화 논리(통제된 실험으로 역치 측정)가 무너지고, 남는 건 "한식 지원"뿐인데 그건 해자가 아니다.

나머지 문항은 전부 보조다.

## 1. 폼 생성 방법 (Apps Script)

### 왜 이 방식인가

| 방법 | 가능 여부 |
|---|---|
| Google Forms MCP 커넥터 | ❌ **레지스트리에 없음** (`search_mcp_registry`로 확인, 결과 0건) |
| **Apps Script** | ✅ **채택.** 2분, 재실행으로 재생성 가능 |
| 브라우저 자동화 | △ 19문항 클릭이라 느리고 깨지기 쉬움 |
| 수동 입력 | 30~40분 |

### 실행 절차

1. https://script.google.com → **새 프로젝트**
2. 기존 코드 전부 지우고 `docs/survey_form.gs` 내용 붙여넣기
3. 상단 **▶ 실행** → 권한 승인 (본인 Drive에 폼 생성됨)
4. **Ctrl + Enter** (또는 메뉴 `보기 → 로그`)로 실행 로그를 열면 3개 링크가 찍혀 있음

```
■ 편집 링크: https://docs.google.com/forms/d/xxxxx/edit
■ 응답 링크: https://docs.google.com/forms/d/xxxxx/viewform
■ 짧은 링크: https://forms.gle/xxxxx
```

### 로그 창을 닫아버렸을 때 링크 다시 보는 법

편집기 왼쪽 사이드바 → **실행(Executions)** 탭(시계 모양 아이콘) → 방금 실행한 `createSurvey` 기록 클릭 → 같은 로그가 다시 나옴.

### 문항 수정 시

스크립트를 고쳐서 다시 실행하면 **새 폼이 하나 더 생긴다.** 이전 폼은 Drive에서 삭제할 것.
(편집 링크로 들어가 폼 UI에서 직접 고쳐도 되지만, 그러면 스크립트와 실물이 어긋난다.)

## 2. 폼 구조 (19문항 / 7섹션)

| 섹션 | 문항 | 목적 |
|---|---|---|
| 1. 참여 확인 | Q1 연령대, Q2 성별, **Q3 증상 빈도** | 스크리닝 |
| 2. 현재 상황 | Q4 회피 음식 수, Q5 회피 근거, **Q6 오귀인 경험**, Q7 날마다 다름 | 명제 4 검증 |
| 3. 기존 시도 | Q8 해본 것, Q9 FODMAP 인지, **Q10 기록 지속 기간**, Q11 중단 이유 | 리텐션 벽 검증 |
| 4. 기록 방식 | Q12 사진 습관, Q13 식전 촬영 의향 | UX 실현 가능성 |
| 5. **챌린지 의향** ⭐ | **Q14 몇 번까지 가능**, Q15 가장 부담되는 점, **Q16 3일 이상 완주 경험** | **핵심** |
| 6. 비용 | Q17 지난 1년 지출, Q18 지불 의사 | BM 검증 |
| 7. 자유 응답 | Q19 (필수 아님) | 정성 |

### 자동 처리되는 것

- ⭐ **Q3 분기**: "거의 없음" 선택 시 **즉시 제출로 이동** → 비대상자 응답 차단
- Q19 제외 **전부 필수**
- **진행률 표시** 켬 (이탈 방지)
- **이메일 미수집** — 개인 식별 정보 없음
- 설명란에 수집 항목·목적·비식별 고지 포함
- 섹션 5 시작 전 페이지 브레이크에 **챌린지 설명문**을 `setHelpText`로 삽입 (Q14를 읽기 전에 무엇에 동의하는지 알게 함)

## 3. 추가 검토된 문항 (아직 미반영)

세션 중 사용자가 별도로 만들던 문항. **원안에 문제가 있어 아래처럼 고칠 것.**

### 원안의 문제

선택지가 `매우 불편함 / 불편함 / 보통 / 적당함 / 경험X` 였는데,
- **"보통"과 "적당함"이 사실상 같은 말** → 응답자가 어느 걸 고를지 혼란, 척도가 꼬임
- **"경험X"는 척도가 아니라 분기 조건** → 5점 척도 사이에 끼우면 평균 계산이 오염됨

### 수정안

> **"음식을 제한하시면서, 그로 인해 일상생활(외식·모임·스트레스 등)에서 느끼는 불편함은 어느 정도인가요?"**

| 선택지 |
|---|
| 전혀 불편하지 않다 |
| 별로 불편하지 않다 |
| 보통이다 |
| 꽤 불편하다 |
| 매우 불편하다 |

**+ 별도로 "음식을 제한하고 있지 않다"를 척도 밖 옵션으로 추가**

### 왜 넣을 가치가 있나

- Q4는 **행동**만 묻고 (몇 가지 피하나)
- Q17은 **돈**만 묻는데 (얼마 썼나)
- 이 문항은 **삶의 질 비용**을 처음으로 묻는다 — "몇 가지 피한다"보다 **"그게 얼마나 괴로운가"가 지불 의사(Q18)와 더 직접 연결**된다

**배치 위치**: Q4 바로 다음 (지금 몇 개 피하나 → 그게 얼마나 불편한가, 자연스러운 흐름)

## 5. ⭐ 분석 계획 — 응답이 모이면 이것부터 본다

### 1순위: Q14 × Q16 교차표

```
Q14 "3번 이상 가능"  ×  Q16 "완주 경험 있음"
              ↓
    이 교집합이 실질적 챌린지 완주 가능 집단

  20% 미만이면 → 제품 축을 스태킹·증상 부검 중심으로 재검토
```

**Q14는 의향(말)이고 Q16은 실적(행동)이다.** Q14만 보면 과대 추정된다 — 사람들은 "할 수 있다"고 말하고 안 한다. **Q16으로 교차검증하는 게 이 설문 설계의 핵심 장치다.**

### 2순위: Q10 (기록 지속 기간)

리텐션 벽의 실증. "1개월 이상" 비율이 낮으면 캐주얼 UX 비중을 더 키워야 한다.

### 3순위: Q6 (오귀인 경험)

명제 4("사용자의 자가 귀인은 대부분 틀리다")의 사용자 측 근거. "있다"가 많으면 킬러 메시지("범인은 8시간 전 점심입니다")가 먹힌다는 뜻.
