# 1. ⭐ 사각형 지연 창 폐기 → 사다리꼴 감쇠 곡선

## 무엇이 뒤집혔나

**폐기된 결론(위키):**
> "실제 발효는 곡선이지만 **MVP에선 사각형이 맞다.** 개인 통과 시간 편차가 창 모양의 오차보다 훨씬 크므로 곡선을 깎아도 그 정밀도가 무의미해진다."

**이걸 무너뜨린 사용자의 질문:**
> "프럭탄이 4시간 안에 소화된다고 치면 그 사람의 역치는 4시간 뒤에 초기화되어야 하는데, 알고 보니 그 사람은 소화시간이 느려서 초기화되면 안 될 수도 있잖아."

## 왜 사각형이 틀렸나 — 절벽형 거짓 음성

```
사각형 창 (폐기)                      사다리꼴 감쇠 (채택)

부하                                  부하
 │████████│                            │    ╱▔▔▔▔╲___
 │████████│← 여기서 뚝 떨어짐          │   ╱          ╲___
 └────────┴──────                      └──╱───────────────╲──
  4h      8h                            head        tail

8h 1분에 부하가 0이 됨.                 서서히 오르고 서서히 사라짐.
소화가 느린 사람은 그때가 정점인데       느린 사람은 tail만 길어지면 됨.
앱은 "0g, 자유롭게 드세요" ❌
```

**사각형의 치명적 결함은 창 모양의 부정확함이 아니라, 꼬리 끝에서 부하가 절벽처럼 0이 된다는 것이다.** 소화가 느린 사용자에게는 바로 그 시점이 실제 발효 정점일 수 있고, 그 순간 앱은 "여유 있음"이라고 거짓 안전 신호를 낸다. → **규칙 5(모르면 위험한 쪽) 정면 위반.**

## 채택하는 모델

그룹마다 두 개의 파라미터를 **따로** 갖는다.

| 파라미터 | 의미 | 어디서 얻나 |
|---|---|---|
| **head (지연·onset)** | 섭취 후 부하가 오르기 시작하는 시각 | 챌린지의 **증상 시작 시각** |
| **tail (감쇠·clearance)** | 부하가 사라지는 데 걸리는 시간 | 챌린지의 **증상 해소 시각** |

**비대칭 규칙: 신뢰도가 낮을수록 tail을 길게 잡는다.** 모르면 부하가 더 오래 남아 있다고 가정하는 쪽이 안전하다.

## 파급 — 이것 때문에 같이 바뀐 것들

1. **증상 로깅이 시작 시각만이 아니라 해소 시각도 받아야 한다** (기존 설계엔 시작만 있었음) → §7
2. **챌린지의 산출물이 1개가 아니라 3개가 된다**: 역치(g) + head + tail → §5
3. 데이터 스키마의 부하 계산이 "창 안의 로그 합산"이 아니라 "각 로그의 감쇠 곡선을 현재 시각에서 평가한 값의 합"이 된다

# 2. 데이터 규칙 8번째 (신설) ⭐

위키의 7규칙에 하나를 추가한다. **이게 이 앱에서 가장 중요한 방어선이다.**

> ### 규칙 8 — 역치 학습의 입력은 **챌린지 데이터로만** 제한한다.
> **일상/캐주얼 식사 기록은 역치 갱신에 절대 쓰지 않는다.**

## 왜

거짓 음성(마늘이 실제로 많이 들었는데 앱이 적다고 계산)이 발생했을 때, 그게 역치까지 오염시키면 **복구 불가능한 손상**이 된다. 잘못 계산된 한 끼가 "이 사람은 프럭탄 6g도 견딘다"로 학습되면 그 뒤 모든 판정이 틀어진다.

**역치 학습을 챌린지로 격리하면, 일상 계산이 아무리 틀려도 역치 자체는 안전하다.** 일상 기록의 부정확함이 그 끼니의 판정 오류로 끝나고 시스템 전체로 번지지 않는다.

## 일상 기록은 그럼 어디에 쓰나

- **증상 부검** (오늘 왜 아팠는지 회고) — 정밀도가 낮아도 되는 용도
- **숨은 성분 탐지** (제거기 목표 대비 위반 발견)
- **개인 보정계수 학습** (양방향, →§4)

# 3. 거짓 음성 7층 방어 체계 ⭐

**전제**: 사진·메뉴명으로 성분을 추정하는 이상 오차는 필연이다. 문제는 오차의 **방향**이다.

## 비대칭 원리

| | 거짓 음성 (과소평가) | 거짓 양성 (과대평가) |
|---|---|---|
| 무슨 일이 | 실제론 마늘 많은데 적다고 계산 | 실제론 적은데 많다고 계산 |
| 결과 | **사용자가 실제로 아프다.** 앱 신뢰 붕괴 → 삭제 | 한 그릇 대신 반 그릇 먹음 |
| 복구 | 어려움 (+ 규칙 8 없으면 역치까지 오염) | 쉬움, 되돌릴 수 있음 |

> **틀리는 비용이 한쪽으로만 크다. 그러므로 모든 기본값을 "위험한 쪽"으로 놓는다.**

## 7개 층

| # | 방어 | 내용 |
|---|---|---|
| **1** | **조리 계열 하한값** | 국·찌개 / 볶음 / 조림 / 무침 등 계열별 최소 프럭탄 값을 둔다. **모르는 한식 요리가 0으로 계산되는 일이 원천적으로 불가능해진다.** 한식은 마늘·양파가 기본이므로 "몰라서 0"은 거의 항상 거짓 음성이다 |
| **2** | **결측 = 계열 평균** | 성분 데이터가 없으면 0이 아니라 계열 평균값을 넣고 **"추정치"로 표시**한다 (규칙 3의 구현) |
| **3** | **범위 저장 + 최댓값 판정** | 함량을 (min, max) 범위로 저장하고, **판정에는 항상 max를 쓴다.** 표시는 범위로 |
| **4** | **OCR + 확인 질문 1~2개** | 라벨을 읽고, 숨은 소스·양념을 잡기 위해 짧게 되묻는다: **"국물도 드셨나요?"** (양파즙·마늘 분말이 국물에 몰려 있음) |
| **5** | **기본 제공량 버튼 = "한 그릇"** | 기본값을 "반"이 아니라 **큰 쪽**으로 둔다. 사용자가 줄이는 건 능동 행동이라 안전한 방향으로만 틀린다 |
| **6** | **긴 tail** | 신뢰도가 낮을수록 감쇠 꼬리를 길게 (→§1). 부하가 조기에 사라지지 않게 |
| **7** | ⭐ **역치 학습 격리** | 위 6개가 전부 실패해도, 잘못된 한 끼가 **역치를 오염시킬 수는 없다** (규칙 8) |

## 8층에 준하는 장치 — 증상 부검의 4번째 상태

증상 부검 결과에 **"계산으로 설명 안 됨"** 상태를 명시적으로 둔다.
- 같은 요리에서 이 상태가 **2~3회 반복**되면 → 사용자에게 확인 요청 → **개인 배수 ×1.5** 상향 적용
- 즉 **시스템이 스스로 자기 오차를 발견하는 경로**가 된다

# 4. 거짓 양성 회복 — 양방향 개인 보정계수

거짓 음성 방어를 강하게 걸면 필연적으로 앱이 과하게 말리게 된다. 명제 3(확장 도구)이 무너지지 않으려면 **반대 방향 복구 경로**도 있어야 한다.

| 장치 | 동작 |
|---|---|
| **하향 보정** | 사용자가 "위험" 경고를 무시하고 먹었는데 괜찮았던 일이 **3회 반복** → 그 요리에 개인 배수 하향 |
| **조정 버튼** | **"마늘 뺐어요"** 같은 사용자 선언 → 즉시 재계산. 외식·특수 상황 대응 |
| **탐색 모드** | 안전 모드가 max + 긴 tail을 쓰는 반면, 탐색 모드는 **중앙값 + 짧은 tail**을 써서 실제 한계를 시험할 수 있게 함 (위키 `역치 정규화` 페이지의 안전/평소/탐색 3모드와 연결) |

→ 상향(§3의 ×1.5)과 하향이 **같은 메커니즘의 양방향**이다.

# 5. 챌린지 설계 확정 사항

## 5-1. 실제 음식의 실중량으로 한다 (순수 파우더 금지) ⭐

**질문이었던 것**: 이눌린 파우더 같은 순수 FODMAP을 쓰면 훨씬 정밀한데 왜 안 쓰나?

**답 — 척도 일관성 때문이다.**

```
파우더로 역치를 재면            템플릿(요리) 기반 일상 판정과
= "순수 물질 척도"의 역치        = "템플릿 척도"의 부하

    이 둘의 척도가 다르다 → 비교 자체가 무의미 → 거짓 음성 재발
```

**핵심 원리: 이 앱은 정확할 필요가 없다. 내부적으로 일관되기만 하면 된다.**
템플릿으로 잰 역치를 템플릿으로 계산한 부하와 비교하면, 템플릿의 비례 오차가 **양쪽에서 상쇄**된다. 파우더를 섞으면 그 상쇄가 깨진다.

> **"정확도보다 일관성"** — 위키 `섭취량 추정` 페이지의 원칙이 챌린지 설계까지 지배한다.

## 5-2. 단위는 무게·부피(g·mL). "몇 쪽"은 금지

마늘 한 쪽의 크기 편차가 너무 커서 계단식 용량의 순서가 깨진다.

## 5-3. 저울은 1회 캘리브레이션으로 충분

- 매번 저울을 쓰라고 하면 완주율이 떨어진다
- 시작할 때 **한 번만** 자기 숟가락 한 술을 재서 등록 → 이후엔 숟가락·컵으로 계량
- **근거**: 숟가락 편차(~±20%)가 계단식 용량 증분(2배·3배)보다 훨씬 작다. **역치 찾기는 "어느 용량에서 증상이 났나"라는 순서(ordinal) 판단이므로 숟가락 편차를 견딘다.**

## 5-4. 챌린지의 산출물은 3개다

| 산출물 | 어디서 |
|---|---|
| **역치 (g)** | 어느 계단에서 증상이 났나 |
| **head (지연)** | 섭취 → **증상 시작** 시각 차 |
| **tail (감쇠)** | 증상 시작 → **증상 해소** 시각 차 |

→ 그래서 증상 로깅이 시작·해소 **둘 다** 받아야 한다 (§1, §7).

## 5-5. 검열 데이터 — 3단계 다 통과한 경우

**"역치 = 최고 용량"으로 기록하면 안 된다.** 얻은 정보는 **"역치 > 최고 용량"**뿐이다.
→ 하한선으로 표시 + 신뢰도 하향 + 다음 챌린지 우선순위 최상단 + 재시도는 더 높은 용량부터. (통계적 정식 처리 방법은 미확인 → `expert-01-questions.md` B-2)

## 5-6. 1회 실패 = 확정 아님

컨디션이 나빴을 수 있다. → 세척 연장 후 컨디션 좋은 시기에 재시도.
**그 관측치는 역치 추정에서 빼고, 컨디션 보정계수 학습에만 쓴다.**
중단 사유를 **증상 / 일정 / 잊음**으로 구분 기록. 안 나누면 "잊어서 못 한 것"이 "실패"로 기록돼 역치를 왜곡한다.

# 6. 소화 속도 개인차 — 4단 신뢰도 체계 (L1~L4)

## 기각한 접근: 나이·성별·활동량·건강상태를 변수로 넣기

**기각 논거 (데이터 희소성):**
> 변수를 하나 추가할 때마다 학습에 필요한 관측일이 **20~30일씩** 늘어난다. 그런데 이 변수들은 전부 **직접 측정 가능한 것의 먼 대리변수**다. 이미 컨디션 체크인·배변 기록·챌린지 실측으로 더 가까운 신호를 받고 있는데, 먼 대리변수를 넣는 건 데이터 예산 낭비다.

**예외 처리:**

| 변수 | 처리 |
|---|---|
| 나이 | **안전 스크리닝에만** 사용 (50세 이후 발병 = 레드플래그). 계산에는 안 씀 |
| 성별 | 변수 대신 **생리주기 기록**(선택, 이벤트 기반)으로 대체 — 더 직접적이고 정확 |
| 활동량·건강상태 | 기존 **아침 컨디션 체크인**에 흡수 |
| 복약 | 입력은 받되, **숫자 배수로 쓰지 않고 그 기간의 판정 신뢰도를 낮추는 데만** 사용 |

## 채택: 정보가 쌓일수록 올라가는 4단 체계

| 층 | 근거 | 정밀도 | 비용 |
|---|---|---|---|
| **L1 표준값** | 문헌 기본값. **tail을 가장 길게** | 낮음 | 0 |
| **L2 아형 보정** | IBS-D ×0.7 / M ×1.0 / C ×1.5 | 낮음 | 0 |
| **L3 배변 보정** | 최근 2주 브리스톨 분포·빈도로 조정 | 중간 | 0 (이미 수집 중) |
| **L4 실측** | 챌린지에서 관측된 head·tail | 높음 | 챌린지 필요 |

### L2에 대한 중대한 단서 ⚠️

**아형 보정은 "방향만 맞을지도 모르는" 거친 초기 추정이며, 정확하지 않다.**
아형은 **대장** 통과를 반영하는데 프럭탄 lag는 **소장** 통과가 지배한다 — **다른 생리 축**이다.
→ 이 가정의 타당성을 의대 교수님께 확인해야 한다 (`expert-01-questions.md` A-5). **"무관하다"는 답이 나오면 L2는 폐기한다.**

### 아형은 고정값이 아니다

IBS 아형은 시간에 따라 변한다. → **배변 기록에서 주기적으로 재도출**해야 한다. 온보딩에서 한 번 받고 끝내면 안 된다.

### 증상 종류별로 창이 다르다

| 증상 | 지배 구간 | 아형 보정의 유효성 |
|---|---|---|
| 팽만·가스 | 소장 통과 비중 큼 | **약함** |
| 급박감·묽은 변 | 대장 통과 비중 큼 | **강함** |
| 크램프 | 중간 | 중간 |

### 선택 기능 후보 — 전체 장 통과시간 자가 측정

옥수수 알갱이를 삼키고 변에서 보일 때까지의 시간을 기록. **비용 0**, 전반적 속도의 거친 보정치를 준다. 단 성분별 보정은 안 되고 전체 통과시간만 나온다.

# 7. ⭐ 증상 로깅의 3-이벤트 문제 (신규 발견)

## 문제

사용자의 질문: *"배가 빵빵하다는 걸 언제 물어봐야 하지? 일반 사용자가 이걸 기록할 리가 없잖아."*

이건 하나의 문제가 아니라 **성격이 다른 세 개의 이벤트**다.

```
식사 ──────────────────────────────────────▶ 시간

① 증상 시작(onset)   ② 증상 해소(resolution)   ③ 무증상(absence)
   "지금 아프다"        "이제 괜찮아졌다"          "챌린지 용량 통과"

   자발 기록 가능 ✅     자발 기록 안 함 ❌         이벤트 자체가 없음 ❌❌
   (아프면 앱을 켬)     (나은 걸 기록할 이유 없음)  (묻지 않으면 영원히 모름)
```

**③이 가장 치명적이다.** 아무 일도 없었다는 것 자체가 정보인데(= 그 용량을 통과했다는 뜻), 능동적으로 묻지 않으면 **"로그가 없다"와 "안 아팠다"를 구별할 수 없다.**

## 해법 — 매번 묻지 않는다. 챌린지 중에만 묻는다

| 모드 | 능동 질문 | 취득 이벤트 | 용도 |
|---|---|---|---|
| **평소(캐주얼)** | **없음.** 아플 때 원탭 기록만 | ①만 | 증상 부검 전용. 정밀도 낮아도 되는 용도 |
| **챌린지 중** (3일, 한 그룹) | **있음.** 하루 2~3회 푸시 | ①②③ 전부 | 역치·head·tail 산출 |

### 챌린지 중 알림 스케줄 (프럭탄 예시)

```
Day 1  아침 소량 섭취
  └─ +2h   "지금 속이 어떠세요?"          ← 소장 구간 체크
  └─ +8h   "지금 속이 어떠세요?"          ← 대장 발효 구간 (프럭탄 lag 창)
  └─ +24h  "어젯밤부터 지금까지 괜찮으셨나요?"  ← 긴 꼬리(tail) 체크
```

**한 그룹당 3일, 하루 2~3회로 끝난다.** 챌린지가 끝나면 알림도 끝나므로 피로도가 관리된다.

**방법론적 근거**: 이건 `research-01`의 참고문헌에 이미 있는 **Fitzke et al. 2024가 쓴 경험표집법(ESM)**과 같은 구조다. 예정된 시점에 짧게 묻는 방식.

## 이게 규칙 8을 다시 정당화한다

```
평소 기록  → ①만 있고 ②③ 없음 → "안 아팠던 순간"을 모름 → 정밀 역치 계산 구조적으로 불가능
챌린지 기록 → ①②③ 전부 확보    → 역치 계산 가능
```

**평소 기록은 구조적으로 절반짜리 데이터라 애초에 역치 계산 재료가 될 수 없었다.** 규칙 8은 임의의 안전장치가 아니라 이 타이밍 문제의 필연적 귀결이었다.

# 8. 미해결 갭 — 과식 vs 발효 가스

**지금 앱은 FODMAP 6축 함량만 추적하고, "총 식사량"은 변수로 없다.** 그래서 "배 빵빵함"이 마늘 때문인지 과식 때문인지 구별 못 한다.

- 가설: 상복부·식후 0~2h = 과식 / 하복부·식후 4~8h+ = 발효 가스
- 대안: "오늘 식사량이 평소보다 많았나요?(적음/보통/많음)" 순서형 자기보고를 교란변수로 추가
- → **의대 교수님 A-4 / 알고리즘 교수님 B-6에서 확인 예정**

# 9. 경쟁 지형 — 위키 주장 2건 정정 ⚠️

위키 `IBS 앱 경쟁 지형과 한국 음식 공백` 페이지에 남아 있는 두 주장이 **사실과 다르다.**

## 정정 ① "시간지연·스태킹 분석 앱은 없다" → **있다**

**Triggerbites**가 실제로 한다:
- **5단계 시간 창** 분석 (0-2h / 2-8h / 8-24h / 24-72h / 3-7일)
- **스태킹 개념을 명시적으로** 사용
- FODMAP·히스타민·살리실레이트·옥살레이트 성분 태깅

**단, 하지 않는 것**: 개인 역치를 **정량화하지 않는다.** 관찰 상관에서 **용의자를 제시**할 뿐이다.

## 정정 ② "한국 저포드맵 데이터가 전무하다" → **절반만 맞다**

| 레이어 | 공백인가 |
|---|---|
| **L1. 정량 성분 데이터** (한식 요리별 프럭탄 g) | ✅ **진짜 공백** |
| **L2. 한국 식재료 매핑·대체 안내** | ❌ **공백 아님.** fodmap.kr(연세 다나이비인후과), 삼성서울병원·세브란스 환자교육 자료 등이 이미 존재. 예: "김치 1/3컵(47g) 이내, 제거기엔 제외", "된장 1큰술 이내" |
| **L3. 요리 → 레시피 분해** | ✅ **진짜 공백.** 아무도 안 함 |

⚠️ fodmap.kr은 출처 표기가 불분명해 **Monash 파생 라이선스 리스크** 가능성이 있다.

## 그래서 진짜 해자는 무엇인가

**한식 지원은 해자가 아니라 입장권(table stakes)이다.** AI로 생성 가능하고 경쟁사도 할 수 있다.

**남는 차별점 2개:**
1. ⭐ **통제된 실험(챌린지)으로 개인 역치를 정량화한다** — Triggerbites 포함 어떤 경쟁사도 관찰 상관에서 용의자만 제시할 뿐 역치를 재지 않는다
2. **축적된 한국 사용자 실로그** — 복제 불가. 단 **출시 후에만 쌓인다** (닭-달걀 문제)

# 10. 캐주얼 사용자 문제 — 시간 분리로 해결

**질문이었던 것**: 챌린지를 완주 안 하는 사용자에게 이 앱이 의미가 있나?

| 기능 | 개인 역치 필요? | 캐주얼 사용자에게 작동? |
|---|---|---|
| **증상 부검** (오늘 왜 아팠나) | ❌ 불필요 | ✅ 완전 작동 |
| **숨은 성분 탐지** | ❌ 불필요 (제거기 목표라는 상수와 비교) | ✅ 완전 작동 |
| 개인 역치·정밀 스태킹 | ✅ 필요 | ❌ 챌린지 필요 |

## 채택한 UX 전략 — 챌린지를 온보딩에서 밀지 않는다

```
1) 캐주얼 일상 사용 (사진 → 3초 판정, 집단 표준 역치 사용)
        ↓
2) 증상 부검이 반복적으로 "애매함/설명 안 됨"으로 끝남
        ↓
3) 그때 앱이 제안: "정확히 알아보시겠어요?" → 챌린지
```

**챌린지를 온보딩 관문이 아니라 사용자가 필요를 느낀 뒤의 자발적 실험으로 재배치한다.**

- **MVP 범위**: 챌린지 결과는 **시뮬레이션 데이터로 데모**. 실제 챌린지 완주는 MVP에 없음
- **단 챌린지 기능 자체를 로드맵에서 빼지는 않는다** — 빼면 §9에서 확인했듯 "한식 지원"만 남고, 그건 해자가 아니다

## ⚠️ 이 프로젝트 최대의 미검증 가정

> **실사용자의 챌린지 완주율이 차별화 논리를 지탱할 만큼 높은가?**

→ 이걸 확인하려고 설문을 만들었다 (`survey-02-form-operations.md`).

# 11. 비즈니스 모델 (최종 확정)

# 13. 이 문서에 담긴 결정의 요약 (한 눈에)

1. 사각형 창 **폐기** → head/tail 사다리꼴 감쇠
2. 데이터 규칙 **8번째 신설** — 역치 학습은 챌린지 데이터만
3. 거짓 음성 **7층 방어** + 자가 발견 경로(부검 4번째 상태)

6. 챌린지는 **실음식 실중량**, 파우더 금지 (척도 일관성)
7. 증상 로깅 **3-이벤트** 구분 + 챌린지 한정 ESM 알림
8. 과식 vs 발효 가스 갭 — **미해결, 교수님 질문으로 이관**
9. 경쟁 주장 **2건 정정** (Triggerbites 존재, 한국 자료 존재)
10. 캐주얼 사용자 → **시간 분리 UX**, 챌린지는 후행 제안
