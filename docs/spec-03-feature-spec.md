# 0. 문서 개요

## 0.1 표기

| 표기 | 의미 |
|---|---|
| 🔴 **필수** | 2주 내 구현. 데모 시연에 반드시 필요 |
| 🟡 **선택** | 시간이 남으면 구현 |
| ⬜ **차기** | 2주 범위 외. 문서에만 기술 |

## 0.2 2주 제약이 만드는 전제

**① 개인 역치는 2주 안에 산출되지 않는다.**
→ 데모는 시뮬레이션 데이터로 시연하고, 발표 시 이를 명시한다.

**② 식품 DB는 전량 구축하지 않는다.**
→ 데모 시나리오용 한식 메뉴 약 50종 + 성분 키워드 약 150개만.

**③ 서버 학습 모델은 만들지 않는다.**
→ 규칙 기반 + 집단 초기값.

## 0.3 용어

| 용어 | 정의 |
|---|---|
| **부하(Load)** | 현재 시각 기준 체내 활성 성분량. 성분별 지연·감쇠 반영 |
| **여유(Headroom)** | 기준선 − 부하 |
| **6축** | 프럭탄 / GOS / 락토스 / 과당 / 소르비톨 / 만니톨 |
| **천장** | 컨디션에 따라 조정된 당일 기준선 |
| **캐주얼 관찰** | 통제 없이 평소대로 먹고 기록만 하는 기본 경로 |
| **재도입** | 특정 음식을 의도적으로 다시 시도하는 선택 경로 |

# 1. 서비스 개요

## 1.1 한 문장

> **먹지 못하는 음식을 찾는 서비스가 아니라, 다시 먹을 수 있는 음식을 찾아가는 서비스.**

## 1.2 세 개의 축

| 축 | 사용자의 질문 | 담당 기능군 |
|---|---|---|
| ① 🍽️ **음식 확인** | "지금 먹고 싶은 이거, 어떻게 먹을 수 있을까?" | RC-01, CA-02, **CA-03** |
| ② 🧠 **개인화 패턴** | "도대체 나는 뭐에 영향을 받는 걸까?" | RC-03, AN-01, AN-02 |
| ③ 🌱 **되찾은 음식** | "처음보다 먹을 수 있는 게 늘었다" | AN-04, PR-02 |

## 1.3 코어 세그먼트

반복적 장 불편을 겪으며 원인을 찾지 못한 **20대 중후반**. IBS 진단 여부 무관.

**설문 근거 (n=61, 유효 52)**
- **"저포드맵 처음 듣는다" 47/52 (90%)** → 진단명·전문용어로 소구하면 안 됨
- **"IBS와 연관 있는 줄 몰랐다" 21/52 (40%)**
- **음식 제한으로 포기 경험**: 여행 중 음식 선택 · 좋아하는 메뉴 주문 · 새로운 음식 시도 (상위 3)

## 1.4 임상적 위치 — 문구를 이렇게 못 박는다

> **ACG 2021**: "훈련된 영양사가 없거나 환자가 비용을 감당할 수 없다면, **고품질 교육자료**를 배포해 환자가 의학적으로 책임 있는 방식으로 식단을 실행하게 하는 것이 중요하다."
> **2025 서울 컨센서스**(한국 현행 가이드라인): "영양사가 없다면 **고품질 교육자료를 사용해야 한다**."

**→ 본 서비스는 진단·치료 서비스가 아니라 "고품질 교육자료(웰니스 관리 도구)"로 포지셔닝한다.** 온보딩에 명시.

# 2. 사용자 여정 — 두 갈래

**v2의 최대 오류는 "제거기 → 재도입"을 모든 사용자의 필수 경로로 둔 것이었다.** 설문에서 이 경로의 진입 장벽이 확인되었으므로, 기본 경로에서 분리한다.

## 2.1 기본 경로 (전원, 통제 없음)

```
① 안전 스크리닝  →  ② 피하는 음식 입력  →  ③ 평소대로 먹으며 사진 기록
                                                      ↓
                                          ④ 증상 있을 때만 원탭 기록
                                                      ↓
                                          ⑤ 패턴 관찰 (며칠~몇 주)
                                                      ↓
                                     ⑥ "이 음식, 다시 시도해볼 만해요" 제안
                                                      ↓
                                        ┌─────────────┴─────────────┐
                                     넘어감                      해보겠다
                                     (계속 ③~⑤)                   ↓
                                                            2.2 선택 경로
```

**⭐ 기본 경로에는 전면 제거기가 없다.** 아무것도 끊지 않고 관찰만 한다.

**근거**: "2~6주 제거기가 최대 이탈 구간인데 그 시기에 할 일이 없다"는 문제를, 전면 제거를 필수에서 빼는 것으로 해소한다. 임상 프로토콜을 그대로 옮기면 이탈하고, 이탈하면 아무 데이터도 안 남는다.

## 2.2 선택 경로 — 상향식(FODMAP gentle) 채택

```
재도입 제안 수락
      ↓
PR-02a  후보 1~2개만 최소 제한        ← 6축 전면 제거 금지
      ↓
PR-02b  분산 반복 단회 도전 (2~3회)   ← 3일 연속 금지
      ↓
      3회 중 2회 이상 재현?
      ├─ 예     → "확인된 후보"
      └─ 아니오 → "판단 보류"
      ↓
결과를 「나의 식탁」에 반영
```

### ⚠️ 용어 정의 — 혼동 주의

| | **하향식 (top-down, 정식)** | **상향식 (bottom-up, FODMAP gentle)** |
|---|---|---|
| 방향의 대상 | **제거 범위** | **제거 범위** |
| 방법 | 6축 전체를 빼고 하나씩 다시 넣음 | 흔한 방아쇠 1~2개만 빼고, 부족하면 더 뺌 |
| 제거 식품 수 | 수십 종 | 한 줌 (마늘·양파·밀·유제품·콩류) |
| 근거 | ✅ 임상시험 입증 | ⚠️ **연구로 정식 평가 안 됨.** Monash 2019~, 실무적 절충안 |
| 적합 대상 | 진단받은 IBS, 감독 하 시행 | 영양 결핍 위험자·성장기·**섭식장애 성향자**·넓은 비진단 인구 |

**MORU는 상향식을 기본값으로 채택한다.**
⚠️ 도전 시 **용량을 올려가느냐(계단식)**와는 **다른 축**이다. 혼동 금지.

**채택 근거 2가지**
- **타깃 정합성** — 설문에서 회피 음식이 "1~2가지"인 응답자가 다수. 뺄 게 별로 없는 사람에게 전면 제거는 의미가 없다
- **부담 요인 직격** — Q17 부담 2위 "그동안 다른 음식을 못 먹는 것"(46.2%)은 도전이 아니라 **제거기 때문에 생기는 부담**이다. 상향식은 이 항목을 상당 부분 소거한다

## 2.3 두 경로의 역할 분담 ⚠️ 중요

| | 기본 경로 (캐주얼 관찰) | 선택 경로 (표적 도전) |
|---|---|---|
| 하는 일 | **어느 성분이 의심되는지 가리킴** | **그게 맞는지 확인** |
| 비유 | 나침반 | 지도 |
| 데이터 품질 | 낮음 (통제 없음) | 중간 (**최소 제한 + 반복 재현**) |
| **개인 등급 갱신** | ❌ **하지 않음** | ✅ **여기서만** |

**데이터 규칙 8**: 개인 등급은 표적 도전 결과로만 갱신한다. 캐주얼 관찰은 "제안 우선순위"에만 쓴다.

⚠️ **상향식은 배경 FODMAP을 통제하지 않으므로 귀인이 정식 프로토콜보다 약하다.** 2-of-3 재현 규칙이 이를 일부 상쇄하지만 완전하지 않다. → 결과 문구는 **"확인된 후보"**까지만. **"확정"이라고 쓰지 않는다.**

# 4. 기능 상세

## 4.1 SF — 안전

### SF-01 · 경고 신호 스크리닝

| 항목 | 내용 |
|---|---|
| **시점** | 온보딩 최초 1회. **다른 어떤 화면보다 먼저** |
| **입력** | 체크박스 — 혈변/흑색변 · 원인불명 체중감소 · 수면 방해 야간통증 · 지속 발열 · 반복 구토 · 빈혈 진단 · 50세 이후 첫 발병 |
| **처리** | **규칙 기반. AI 사용 금지** |
| **출력** | 해당 시 안내 화면 + 진입 차단 |
| **예외** | "이미 병원에서 확인함" 선택 시 진입 허용, 기록 보관 |
| **금지** | 질병명 판정 문구 |

⚠️ **미확인**: 이 항목 리스트의 1차 출처(NICE CG61 / ACG)를 원문 대조하지 못했다. 의대 교수님 확인 필요 → `expert-01-questions.md` A-2

### SF-03 · 경고 신호 상시 감시 ⭐ 승격

**메모2 지적 반영**: *"위험신호는 상시 감시해야지 입구에서 한 번 봐서는 안 된다"*

| 항목 | 내용 |
|---|---|
| **목적** | ① 온보딩 이후 발생한 경고 신호 포착 ② **앱이 사용자를 해치고 있는지 감시** |
| **감시 대상 A (의학)** | 증상 기록에 혈변 항목 상시 노출 → 체크 시 즉시 병원 안내 |
| **감시 대상 B (제한 확대)** | 피하는 음식 개수가 지속 증가 / 기록되는 식사 종류가 지속 감소 |
| **출력** | A: 즉시 안내 · B: 부드러운 알림 + 필요시 전문가 상담 안내 |
| **⭐ 연동** | B 감지 시 → **PR-04 확장 제한 옵션 제안을 차단**하고, CA-02b 확장 판정도 중단 |
| **왜 필수인가** | 패턴을 보여주는 앱은 **구조적으로** 회피 목록을 늘리는 압력을 만든다. 자기가 만드는 위험을 자기가 감시해야 한다 |

**⚠️ 상향식 채택이 이 위험을 줄이는 1차 방어다.** FODMAP gentle이 권장되는 대상이 **섭식장애 성향자·영양 결핍 위험자**인 것과 같은 이유다. SF-03은 그 위에 얹는 2차 방어.

### SF-02 · 절대 배제 등록

| 항목 | 내용 |
|---|---|
| **입력** | 알레르기 식품 / 셀리악 진단 여부 |
| **처리** | 별도 테이블. **모든 판정 로직 최선두에서 필터** |

## 4.3 RC — 기록

### RC-01 · 음식 확인 ⭐ 제품의 척추

**구 RC-01(사진) + RC-04(OCR)를 통합.** 입력 수단이 무엇이든 하나의 흐름.

| 항목 | 내용 |
|---|---|
| **입력 수단** | ① 음식 사진 ② 메뉴 검색 ③ 직접 입력 ④ 원재료명 사진(OCR) |
| **처리** | 사진 → **메뉴 식별만**(LLM) → 레시피 템플릿으로 성분 분해 → 사용자 확인·수정 |
| **양 입력** | 버튼 3개 (반 / 한 그릇 / 한 그릇 반 이상). **기본값 = "한 그릇"** |
| **⚠️ 원칙 1** | **사진으로 양을 추정하지 않는다.** 양념에 갈린 재료는 원리적으로 식별 불가 |
| **⚠️ 원칙 2** | **AI가 전부 판단하지 않는다.** AI가 재료 후보를 제시하고 **사용자가 체크·수정** |
| **확인 질문** | 1~2개 짧게. 예: *"국물도 드셨나요?"* (양파즙·마늘 분말이 국물에 몰림) |

**메모2 지적에 대한 답**: *"밖에서 먹는 음식은 마늘이 몇 쪽 들어갔는지 확인이 어렵다"* — 맞다. 그래서 **정확도가 아니라 일관성**을 목표로 한다. 같은 요리는 항상 같은 방식으로 추정되므로, 비교(지난주 vs 오늘)는 유효하다. 절대값의 정확도는 애초에 요구하지 않는다.

**사용자 확인 화면 예**

```
📷 김치찌개

AI 추정 재료 — 맞는 것만 남겨주세요
  ☑ 김치      ☑ 돼지고기
  ☑ 양파      ☑ 마늘
  ☐ 대파      ＋ 직접 추가

양은 어느 정도 드셨나요?
  [ 반 ]  [ 한 그릇 ✓ ]  [ 한 그릇 반 이상 ]

국물도 드셨나요?   [ 네 ]  [ 아니요 ]
```

| 항목 | 내용 |
|---|---|
| **목적** | **"먹지 마세요" 대신 "이렇게 바꾸세요"** |

**왜 승격인가**: 기본 경로에는 제거기가 없지만, 사용자가 스스로 음식을 제한하는 시기는 여전히 존재한다. 그 시기에 앱이 줄 수 있는 유일한 즉각적 가치가 대체 제안이다. **"할 일이 없는 구간"을 채우는 기능.**

### CA-06 · 일정 연동 관리 ⭐ 신설

| 항목 | 내용 |
|---|---|

### PR-02b · 분산 반복 단회 도전 🔴 ⭐ 핵심

**3일 연속 증량 대신, 중간 용량 단회 도전을 여러 날에 흩뿌려 2~3회 반복한다.**

```
❌ 정식:  Day1 소량 → Day2 2배 → Day3 3배   (연속 3일)
⭕ 채택:  1주차 아무 날 하루 · 우유 200ml → 다음날 아침 기록
          2주차 아무 날 하루 · 동일
          3주차 아무 날 하루 · 동일
```

| 항목 | 내용 |
|---|---|
| **판정 규칙** | **3회 중 2회 이상 재현 시 "확인된 후보"**. 이하는 **"판단 보류"** |
| **워시아웃** | 도전일 전후 1~2일 해당 후보 재섭취 금지 **권고**(강제 아님)<br>⚠️ **프럭탄 계열(마늘·양파·밀)은 2일 이상**을 기본값으로 — 감쇠 꼬리가 길다 |
| **한 번에 하나** | 여러 후보 동시 도전 금지 |
| **컨디션** | 나쁜 날은 미루도록 안내 (하드 블록 아님) |
| **안심 문구** | *"증상이 나더라도 장에 손상이 가지는 않습니다"* (Gloucestershire NHS 원문) |
| **중단 사유 구분** | 증상 / 일정 / 잊음 |

**⭐ 왜 2-of-3인가 — 1회 판정은 쓸 수 없다**

| 근거 | 수치 |
|---|---|
| 노시보 | 이중맹검에서 **포도당 위약이 26% 증상 유발** (Van den Houte 2024) |
| 단회 재현성 | 불내성 판정 **κ = 0.72** = 약 13% 불일치 (Wilder-Smith 2019) |

**1회로 확정하면 4명 중 1명꼴로 애먼 음식을 끊게 만든다.** 반복 재현이 이를 직접 막는다.

**⭐ 설문 근거 — 부담을 싼 축으로 옮긴다**

```
비싼 축:  "3일 연속 지켜야 하는 것"   전체 51.9% / 도전 포기 그룹 81.3%  ← 1위
싼 축:    "여러 번 반복해야 하는 것"   전체 11.5%                        ← 최하위권
```

**정확도를 깎아 부담을 줄인 것이 아니라, 같은 정보를 더 싼 축으로 옮긴 것이다.**

# 5. 데이터 정의

## 5.1 저장 원칙 8가지

| # | 규칙 |
|---|---|
| 1 | 식품은 "위험/안전" 속성을 갖지 않는다. **함량 값만** 갖는다 |
| 2 | 부하는 **"지금 시각 기준 성분별"**. 날짜 합계는 실시간 판정에 쓰지 않는다 |
| 3 | **없는 데이터는 0이 아니다.** 미측정과 0을 구분해 저장·표시 |
| 4 | 개인 등급은 덮어쓰지 않고 이력으로 쌓는다 |
| 5 | **모르면 위험한 쪽으로** 가정한다 |
| 6 | 등급에 측정 출처(기준 식품·템플릿 버전·시점)를 함께 저장 |
| 7 | 부하 추정치에 **신뢰도**가 따라붙는다 (단순 식품 ≠ 복합 요리) |
| **8** | ⭐ **개인 등급은 재도입 결과로만 갱신한다.** 캐주얼 관찰은 제안 우선순위에만 쓴다 |

## 5.2 시간축 — 사각형 창 폐기

**성분별로 두 파라미터를 갖는다.**

| 파라미터 | 의미 | 얻는 곳 |
|---|---|---|
| **head** | 부하가 오르기 시작하는 지연 | 문헌 기본값 |
| **tail** | 부하가 사라지는 감쇠 기간 | 문헌 기본값, 재도입 시 실측 |

```
❌ 사각형 창           ⭕ 사다리꼴 감쇠
 │████████│            │   ╱▔▔▔╲___
 └────────┴──          └──╱────────╲──
  꼬리에서 절벽           서서히 사라짐
  → 느린 소화자에게        → 신뢰도 낮을수록
    거짓 음성                tail을 길게
```

## 5.3 초기 기준값 (문헌 기반)

| 그룹 | 초기값 | 근거 강도 |
|---|---|---|
| **락토스** | **한국 IBS 6~8g/회**로 시작 (서구 표준 12g 대비 하향) | **강함** — 메타분석 + NIH 합의 + 한국인 데이터 |
| **과당** | 건강인 25g → **IBS 10~12g/회** | 중~강 (건강인 대상) |
| **소르비톨** | 5g 경계 / 10g 경증 / 20g 중증 | 중간 (건강인, 오래된 연구) |
| **프럭탄** | ❌ 단일 숫자 불가 → 곡선으로 | **약함 — 문헌 정면 충돌** |
| **GOS** | ❌ 불가 | 매우 약함 — 문헌 역전 |
| **만니톨** | ❌ 불가 | 매우 약함 |

**⚠️ 프럭탄 충돌**: 건강인은 5g/일 무증상, IBS/NCGS는 **2g/일에서 유의 증상**. 건강인 데이터를 IBS 사전분포로 쓰면 위험하다.

**⚠️ 문헌 챌린지 용량은 한국인 습관 섭취의 4~120배다.** 그대로 쓰면 극단적 과대추정.

## 5.4 한국인 기준선 (Na & Sohn 2023, n=787)

| FODMAP | 한국 IBS군 (g/일) |
|---|---|
| **프럭탄** | **4.6 ± 2.2** ← 최다 |
| 락토스 | 4.2 ± 4.7 |
| 초과 과당 | 0.9 ± 1.9 |
| 소르비톨 | 0.8 ± 1.4 |
| 만니톨 | 0.4 ± 0.5 |
| GOS | 0.1 ± 0.1 |
| **총합** | **11.2 ± 7.3** (서구 20~30) |

**⭐ 양파 + 마늘이 한국인 프럭탄 섭취의 약 70%.**

**→ 설계 함의: 프럭탄을 하나의 그룹으로 다루지 말고 양파/마늘/밀을 각각 다룬다.** 통과율도 양파 57% / 마늘 62% / 밀빵 74%로 17%p씩 벌어진다.

**→ GOS·만니톨은 노출 자체가 드물다.** 등급 추정 대상에서 후순위로 두고 "데이터 부족"을 명시한다.

## 5.5 주요 데이터

| 구분 | 내용 |
|---|---|
| **성분 그룹** | 6개 고정. 각각 head/tail 보유 |
| **식품** | 이름·분류·기본 제공량·**포도당 함량**(과당 초과분 계산용) |
| **성분 함량** | "식품 × 성분" 조합마다 1행. **행이 없으면 미측정.** **(min, max) 범위로 저장, 판정엔 max 사용** |
| **레시피 템플릿** | 조리 음식 → 재료 구성. 조리법별 잔존율 |
| **조리 계열 하한값** | 국·찌개 / 볶음 / 조림 / 무침. **모르는 한식이 0으로 계산되는 것을 원천 차단** |
| **성분 키워드 사전** | OCR 매칭용 약 150개 |
| **사용자 기록** | 식사(시각 필수) / 증상(3종 + 시작·해소 시각) / 체크인 |
| **사용자 상태** | 개인 등급(append-only) / **절대 배제 목록**(계산과 분리) |

## 5.6 2주 구축 범위

```
한식 메뉴 레시피 템플릿   약 50종
성분 키워드 사전          약 150개
성분 함량
  과당·락토스        → 국가표준식품성분표
  프럭탄·GOS·폴리올  → 문헌 + 국내 병원 공개 자료 기반 추정
```

⚠️ **모든 추정값에 신뢰도 `estimated` 표시.**
⚠️ **한식 발효 장류(김치·된장·고추장)의 정량값은 세계 어느 자료에도 없다.** 초기 버전에서는 "혼합 FODMAP"으로 분류하고 재도입 대상에서 제외한다.

# 6. AI 활용 명세

## 6.1 원칙

> **AI는 입력과 출력에 쓰고, 판정에는 쓰지 않는다.**

```
사진·자연어 → [AI 파싱] → 결정론적 계산 → [AI 설명] → 사용자
```

**⚠️ 오해 방지**: 이것은 "AI를 적게 쓴다"는 뜻이 아니다. **요리 하나에서 6축 성분을 동시에 추정하는 것은 AI만 할 수 있는 일**이고, 앱에서 가장 무거운 연산이다.

## 6.2 용도별

| 용도 | 시점 | 비고 |
|---|---|---|
| 메뉴 → 재료 분해 템플릿 생성 | **빌드타임** | 결과를 DB에 고정. 같은 음식은 항상 같은 값 |
| 사진 → 메뉴 식별 | 런타임 | **식별만.** 양 추정 안 함 |
| 재료 후보 제시 | 런타임 | **사용자가 확인·수정** |
| 원재료명 OCR | 런타임 | 텍스트 추출 후 사전 매칭 |
| 패턴 분석 결과 서술 | 런타임 | 계산은 코드, 서술만 AI |
| 대체 제안 | 빌드타임 + 런타임 | |

## 6.3 금지

| 금지 | 이유 |
|---|---|
| 판정을 AI에게 | 같은 질문에 다른 답 → 일관성 붕괴 |
| **경고 신호 판정** | 환각이 사람을 다치게 함. **규칙 기반 필수** |
| 사진으로 양 추정 | 원리적으로 불가 |
| 매 요청마다 레시피 재생성 | 같은 음식이 매번 다른 값 |
| 자유 상담 챗봇 | 의료 질문 유입. 규제 위험 |

## 6.4 프롬프트 제약 ⚠️ 메모2 지적 반영

> LLM에 질의하면 **IBS와 관련이 적은 글루텐·염증성 질환이 섞여 나오는 경우가 있다.**

**대응**
- 출력 스키마를 고정한다 (6축 성분명만 허용, 자유 텍스트 금지)
- 허용 어휘 화이트리스트 — 질병명·진단 용어 출력 차단
- 후처리 필터 — 금지어 감지 시 응답 폐기 후 재요청
- **셀리악/글루텐은 SF-02(절대 배제)에서만 다루고, 성분 분석 경로에서는 언급 금지**

# 7. 신뢰 유지 설계 ⚠️ 메모2 지적 반영

> *"괜찮대서 먹었는데 아팠다가 반복되면 사용자는 앱을 불신하게 된다"*

**예측 실패는 반드시 일어난다.** 실패를 없애는 것이 아니라 **실패해도 신뢰가 유지되는 구조**를 만든다.

| 장치 | 내용 |
|---|---|
| **① 애초에 단정하지 않는다** | CA-02가 "먹어도 됩니다"라고 말하지 않으므로, 틀려도 "약속을 어긴 것"이 되지 않는다 |
| **② 불확실성을 먼저 밝힌다** | *"다만 수면 부족이 겹쳐 확정은 아닙니다"* |
| **③ 틀렸을 때 물어본다** | *"예상과 달랐네요. 혹시 이런 게 있었나요?"* → 스트레스·수면·식사량 선택지 |
| **④ 개인 보정** | 같은 요리에서 예측 실패 2~3회 누적 → 그 요리의 추정치 상향/하향 조정 |
| **⑤ 실패를 자산으로 표현** | *"이번 기록 덕분에 추정이 조금 더 정확해졌어요"* |
