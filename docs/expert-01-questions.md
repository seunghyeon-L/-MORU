# A. 의대 교수님 질문 5개

우선순위: **1 → 4 → 5** (시간이 짧으면 여기까지). 2·3은 여유 있을 때.

---

## A-1. 챌린지 안전성 ⭐ 최우선

> **"재도입(챌린지)을 의사 감독 없이 앱만으로 유도해도 안전한가요? 앱이 반드시 넣어야 할 안전장치가 있을까요?"**

### 우리가 이미 넣어둔 안전장치 (이걸 먼저 보여주고 시작할 것)

- 온보딩에서 레드플래그·알레르기·셀리악이 걸러진 사람은 **챌린지 진입 자체를 차단**
- 컨디션(수면·스트레스)이 나쁜 날엔 **챌린지 시작 금지**
- **한 번에 한 그룹만.** 동시 다중 챌린지 금지
- **3일 계단식(소→중→대)** 증량. 갑자기 큰 용량부터 시작하지 않음
- 알레르기로 등록된 식품은 **챌린지 로직 자체가 우회** (용량 조언을 아예 하지 않음)
- 챌린지 사이 **세척 기간 2~3일**

### 못 채운 것

이 정도로 충분한지, 아니면 **의학적으로 반드시 넣어야 하는데 저희가 모르는 안전장치**가 있는지 확인 못 함.

### 왜 이게 1순위인가

**일부러 증상을 유발하는 기능**이라 윤리적으로 가장 취약한 지점이다. 서비스 자체의 위험성 질문이므로 다른 무엇보다 먼저 확인받아야 한다.

## A-2. 온보딩 레드플래그

> **"IBS 진단 온보딩 과정에서, 혈변·빈혈·50세 이후 발병 말고 다른 심한 병을 걸러내기 위해 꼭 물어봐야 하는 질문이 더 있을까요?"**

### 우리가 이미 넣은 항목과 그 근거

| 신호 | 왜 넣었나 |
|---|---|
| **혈변·흑색변** | IBS는 로마 IV 정의상 **출혈을 일으키지 않는 기능성 질환**. 출혈은 구조적 손상(대장암·염증성장질환·게실 출혈) 신호 |
| **빈혈** | IBS는 빈혈을 만들지 않음. 빈혈이 있다면 **눈에 안 보이는 만성 출혈** 의심 |
| **50세 이후 첫 발병** | IBS는 통상 젊을 때 시작. 대장암은 50세 이후 발병률 급상승(대장암 검진 시작 연령이 전통적으로 50세) → 통계적으로 다른 원인일 확률이 올라감 |
| 의도치 않은 체중 감소 | 악성 질환·흡수장애 신호 |
| 야간 통증·설사 (자다가 깰 정도) | 기능성 질환은 통상 수면 중 증상을 잘 일으키지 않음 |
| 대장암/IBD/셀리악 가족력 | 유전적 위험 |
| 발열, 만져지는 복부 덩어리 | 염증성·종양성 신호 |

### 못 채운 것

**이 리스트의 1차 출처(가이드라인 원문)를 특정하지 못했다.** `research-01`에도 이 항목만은 근거 문헌 없이 일반 임상 상식으로 적혀 있다.

### 참고 — 우리가 파악한 가이드라인 3종의 역할 차이 (교수님이 먼저 언급하시면 알아듣기 위한 배경지식)

| 가이드라인 | 정체 | 레드플래그와의 관계 |
|---|---|---|
| **로마 IV (Rome IV)** | IBS를 "무엇으로 정의할 것인가"의 진단 기준 자체 (복통 주 1회 이상 + 배변 관련 + 3개월 이상 등) | **양성 진단 기준**이 중심. "이건 IBS가 아니다"를 거르는 쪽은 아님 |
| **ACG (미국소화기학회)** | IBS 진료·관리 임상 가이드라인. 최신판 2021년(Lacy 등), AJG 게재 | 진단·검사·치료 권고 안에 **알람 기능(alarm feature)** 섹션 포함 |
| **NICE CG61 (영국)** | 성인 IBS 진단·관리 국가 가이드라인 | **레드플래그를 명시적으로 나열**하는 것으로 유명. 직장출혈·원인불명 체중감소·대장암/난소암 가족력·60세 이상 6주 이상 지속되는 배변습관 변화·빈혈·촉지되는 덩어리·염증수치 상승 등 |

**우리 리스트는 사실상 NICE CG61 축약본과 거의 같은 내용**이지만, 원문 인용이 아니라 재구성이라 정확한 문항 수·정의(예: "6주 이상 지속" 같은 기간 조건)까지는 못 맞췄다.

## A-3. 컨디션 보정 요인

> **"컨디션(수면·스트레스·생리주기·최근 감염)이 역치에 영향을 준다는 가정, 임상적으로 봤을 때 빠진 요인이 있나요?"**

### 우리가 이미 확인한 근거

**수면 — 근거 강함. 이건 확정된 사실로 말해도 됨.**

| 연구 | 방법 | 결과 |
|---|---|---|
| Buchanan et al., *J Clin Sleep Med* 2014 | 액티그래피(손목 밴드, 객관) + 주관적 수면 질 설문 동시 측정 | **액티그래피 수면 효율 → 다음날 복통 예측 실패**<br>**주관적 수면 질 → 다음날 복통·불안·피로 예측 성공** |
| Fitzke et al., *Am J Gastroenterol* 2024 | 스마트폰 실시간 설문(ESM·경험표집법) | 같은 결론 반복. 저자들이 직접 **"수면의 지각(perception)이 가장 영향력 있는 요인일 가능성"** 제시 |

→ **서로 다른 연구팀이 10년 간격으로 같은 결론.** 이게 웨어러블을 MVP에서 빼고 "어젯밤 잘 주무셨나요?(1~5)" 슬라이더 하나로 대체한 근거다.

### 못 채운 것

수면 외 3개(스트레스·생리주기·감염후IBS)는 **"그럴 것이다" 수준으로만** 넣었다. 빠뜨린 요인이 있는지, 혹은 이 중 효과가 약해서 뺄 수 있는 게 있는지 미확인.

### 좋은 후속 질문

"이 주관>객관 현상이 IBS에 국한된 건가요, 일반적인 통증 지각에도 똑같이 적용되나요?"

## A-4. 과식 vs FODMAP 발효 가스 구별 ⭐ 실용성 최고

> **"단순 과식으로 인한 위 팽창과, FODMAP 발효로 인한 대장 가스 팽만이 증상의 위치나 발생 시점에서 임상적으로 구별되는 특징이 있나요? 저희는 '상복부·식후 이른 시점 = 과식', '하복부·식후 늦은 시점 = 발효 가스'로 추정하고 있는데, 이게 맞는 방향인가요?"**

### 왜 이 질문이 필요한가 — 설계상의 실제 구멍

지금 앱은 **FODMAP 6축의 함량만 추적**한다. "오늘 총 얼마나 많이 먹었는지(전체 식사량·부피)"는 **변수로 아예 안 들어가 있다.**

```
"배가 빵빵하다"는 같은 증상 보고가 두 원인에서 나온다 — 지금 앱은 구별 불가

원인 A: FODMAP 발효 가스        원인 B: 단순 물리적 과식
  대장에서 박테리아가              위/장에 음식 자체가
  프럭탄·GOS를 발효                많이 들어차서 늘어남
  → 함량의 문제                    → 포드맵 함량과 무관, 순수 "양"의 문제
```

사용자가 "배 빵빵함"을 기록해도 **마늘 때문인지 그냥 많이 먹어서인지 앱이 구별을 못 한다.**

### 우리가 세운 가설 (검증 안 됨)

| | 위 팽창 (과식) | FODMAP 발효 가스 |
|---|---|---|
| **위치** | 상복부·명치 (위가 있는 곳) | 하복부 (대장이 있는 곳) |
| **시점** | 식후 0~2시간 (위 배출 시간) | 식후 4~8시간+ (대장 도달·발효 시간, 우리 lag 모델과 일치) |
| **성격** | 빵빵하게 찬 느낌, 트림으로 완화 | 방귀로 완화, 쥐어짜는 느낌 동반 가능 |

### 이 답으로 우리가 할 일

**"맞다"면** → 증상 로깅에 **"어디가 불편한가(상복부/하복부)"** 축 하나만 추가하면 이 갭이 메워진다. 지금은 팽만/크램프/급박감 3종만 있고 위치 축이 없다.
**"아니다/겹친다"면** → "오늘 식사량이 평소보다 많았나요?(적음/보통/많음)" 자기보고 항목을 교란변수로 추가하는 쪽으로 간다 (→ B-6 질문과 연결).

### 참고 — 이 질문은 원래 다른 형태였다

처음엔 **"소화량 초과로 아픈 것 vs 뇌가 오판하는 것을 구별할 필요가 있나요?"**로 물으려 했으나, 실용성이 낮아 위 형태로 교체했다. 다만 배경 지식으로는 알아둘 것:

- Wu 2022 / Major 2017이 보여준 건 **IBS 환자와 건강인의 장내 가스량·팽창 정도가 거의 같았는데 IBS 환자만 아팠다**는 것 → 실제로 관찰되는 건 대부분 **"뇌의 오판"(내장 과민성)** 쪽
- 다만 이 구분이 실제로 중요해지는 지점이 하나 있다: **챌린지 최고 용량을 얼마까지 올려도 안전한가.** 과민 반응만 있는 사람이면 "아픈 것"이지 "장이 다치는 것"은 아니지만, 물리적 한계 초과가 섞이면 최고 용량 설정 자체가 안전 문제가 된다 → **A-1과 합쳐서 물어도 되는 내용**

## A-5. 아형이 소장 통과 시간의 대리 지표가 되는가

> **"IBS 아형(C/D/M)이 소장 통과 시간의 대리 지표로 쓸 만한가요, 아니면 완전히 다른 축인가요?"**
> 쉽게 풀면: **"대장 통과 속도(아형)를 알면 소장 통과 속도(프럭탄 지연시간)를 짐작할 수 있나요, 아니면 서로 무관한 값인가요?"**

### 배경 — 두 개의 서로 다른 "속도계"

```
음식 →  [소장 통과]  →  [대장 통과]  →  배출
          ↑                  ↑
    프럭탄 발효·가스가      아형(C/D/M)을
    시작되는 구간            정의하는 구간
    (= 우리가 쓰는 lag)      (= 변의 굳기)

같은 몸 안이지만 서로 다른 두 개의 속도계
```

- **아형은 브리스톨 대변 척도로 정의** → 변이 딱딱/무름은 **대장**에서 물을 얼마나 흡수했는지, 즉 **대장 통과 속도**를 반영
- **프럭탄 발효는 소장을 지나 대장 초입에 도달했을 때 시작** → **소장 통과 속도**가 지배

### 우리가 세운 가설 (검증 안 됨)

소장 속도계를 직접 잴 방법이 없으니, 이미 갖고 있는 대장 속도계(아형)로 추정하기로 **잠정** 처리했다.

| 아형 | 지연시간 보정 배수 |
|---|---|
| IBS-D | ×0.7 (빠름) |
| IBS-M | ×1.0 |
| IBS-C | ×1.5 (느림) |

**이건 "IBS-D는 장이 전체적으로 빠르니 소장도 빠르지 않을까"라는 추측이다.** 소장과 대장은 서로 다른 근육·신경 지배를 받으므로, 이 상관이 실제로 성립하는지 독립적인 두 변수인지 우리 지식 밖이다.

### 이 답으로 우리가 할 일

**"무관하다"면** → 아형 기반 보정(L2)을 폐기하고, 배변 기록 기반 보정(L3)과 챌린지 실측(L4)에 더 의존해야 한다. 4단 신뢰도 체계(→ `spec-02-design-updates.md` §3)의 한 층이 통째로 빠지는 셈이라 설계에 직접 영향.

# B. 알고리즘 교수님 질문 6개

의학 질문 말고 **"이 계산 구조가 통계·알고리즘적으로 맞는 접근인가"**를 묻는다.
우선순위: **1 → 2 → 5**.

---

## B-1. 극소 데이터에서의 개인 역치 추정 ⭐ 최우선

> **"한 사용자당 데이터가 극도로 적은 상황(그룹당 챌린지 1~2회)에서 개인 역치를 추정하려고 합니다. 이게 N-of-1 실험 설계나 심리물리학의 계단식(staircase / up-down) 역치측정법과 비슷한 것 같은데, 이런 문제에 적합한 알려진 방법론이 있을까요?"**

**배경**: 저희가 설계한 "3일 계단식 용량 증가(소→중→대) + 세척기간 2~3일"이 우연히 심리물리학의 역치 측정법과 구조가 유사한데, **직접 재발명한 것이라 검증이 필요**합니다.

**얻고 싶은 것**: 기존 방법론의 **이름**. 이름을 얻으면 그대로 문헌 인용이 되고, §3.1 초기 역치값 설정 근거도 같이 확보됩니다.

## B-2. 검열(censored) 데이터 처리

> **"챌린지 3단계를 모두 통과해서 '역치 > 최고 용량'만 아는 경우를 통계적으로 어떻게 다루는 게 맞나요? 생존분석의 우측 절단(right-censoring) 개념을 그대로 써도 될까요?"**

**우리 임시 처리**: "이 값은 하한선"으로 표시 + 신뢰도 낮춤 + 다음 챌린지 우선순위 최상단 + 재시도는 더 높은 용량부터.

**왜 중요한가**: 이걸 "역치 = 6g"으로 기록하면 시스템이 사용자를 **영구히 과소평가**하고, 6으로 나눈 비율이 부풀려져 **다른 그룹까지 덩달아 경고**를 받는다 → 명제 3(확장 도구) 위반.

## B-3. 계층 베이지안이 과한가

> **"개인 데이터가 부족할 때 집단 평균(population prior)과 개인 데이터를 섞고 싶은데, 이 정도 스케일(해커톤 2주, 사용자 수 적음)에서 계층 베이지안이 오버엔지니어링일까요, 아니면 오히려 정답에 가까울까요?"**

도메인 지식만으로는 이게 과한 설계인지 판단이 안 섭니다.

## B-5. 감쇠 곡선의 초기화

> **"FODMAP 그룹별 부하를 시간에 따라 감쇠하는 곡선(사각형이 아니라 사다리꼴)으로 모델링하려는데, 데이터가 거의 없는 상태에서 곡선 모양을 추정하는 합리적인 최소 접근이 있을까요?"**

## B-6. 순서형 교란변수 삽입

> **"'식사량이 평소보다 많았다'는 자기보고 체크박스 하나를 FODMAP 스태킹 비율 계산에 교란변수로 넣고 싶은데, 이런 3단계 순서형 변수(적음/보통/많음)를 기존 회귀·베이지안 모델에 깔끔하게 끼워 넣는 방법이 있을까요?"**

→ **A-4(의대)와 짝을 이루는 질문.** A-4에서 "위치·시점으로 구별 안 된다"는 답이 나오면 이 경로가 대안이 된다. 절대량(g·kcal)을 재지 않아도 되는 게 장점.

# C. 질문 진행 요령

1. 각 리스트에서 **상위 2~3개만 추리고** 나머지는 "시간 되시면"으로 붙인다. 두 분 다 시간이 짧을 가능성이 높다.
2. 질문 전에 **"저희가 여기까지는 조사했습니다"**를 30초 안에 요약해서 먼저 말한다. 교수님이 설명 안 해도 되는 부분을 건너뛸 수 있어 실제 답변 밀도가 올라간다.
3. **답변 중 언급되는 문헌·가이드라인 이름은 반드시 받아 적는다.** 우리가 못 채운 출처가 여기서 나온다.
4. 답변을 받으면 이 문서에 `### 교수님 답변` 섹션을 각 질문 아래에 추가하고, 영향받는 설계 문서(`spec-02-design-updates.md`)를 갱신한다.
