## A. 포지셔닝 / 타겟

### A-1. "IBS 앱"이라고 부르지 않는다

- 대부분의 당사자는 **자기가 IBS인 줄 모른다** → 진단명으로 타겟하면 시장이 좁아진다
- 진단명 라벨링은 **의료기기 규제 리스크**를 키운다
- IBS는 정상 반응과 연속선상에 있는 **스펙트럼**이다. 로마 IV 기준선은 자연에 존재하는 경계가 아니라 인위적으로 그은 선이다

```
겉으로 내세우는 것 → "먹고 나면 배가 아픈 사람을 위한 앱" (증상 기반)
내부 로직         → FODMAP 정량 + 개인 역치 학습
```

### A-2. FODMAP은 개별 불내성들의 합집합이다

별도 로직 없이 이미 커버되는 것들:

| FODMAP 하위 그룹 | 사실상 커버하는 것 |
|---|---|
| 락토스 | 유당불내증 (동아시아 유병률 높음 → **한국 시장에서 중요**) |
| 과당 | 과당흡수장애 |
| 프럭탄 | "빵 먹으면 더부룩" 비셀리악 밀 민감성의 상당수 |
| GOS | "콩 먹으면 가스 차는" 사람 |
| 폴리올 | "무설탕 껌 씹으면 설사하는" 사람 |

**프럭탄과 GOS는 인간이 분해 효소를 아예 갖고 있지 않아 100% 흡수 불가다.** 흡수 불량은 병이 아니라 인간의 기본 사양이고, IBS 환자는 그 결과를 견디는 **역치가 낮을 뿐**이다.
→ 진단명 없는 사용자에게도 앱이 유효하다는 생리학적 근거.

### A-3. 경쟁 상대는 다른 FODMAP 앱만이 아니다

장 지향 최면요법이 저포드맵과 **동등한 효과**를 낸다 (Peters et al. 2016, RCT). 심리 개입 앱(예: Nerva)도 같은 시장이다.
→ 장기 확장 경로로 심리 개입 축을 검토할 것.

## B. 안전 설계 — 온보딩 게이트

### B-1. 레드플래그 스크리닝 (필수)

하나라도 해당 시 **식이 조언을 하지 않고 병원 안내**:
- 50세 이후 처음 시작된 증상
- 혈변 / 흑색변
- 의도하지 않은 체중 감소
- 자다가 깰 정도의 야간 통증·설사
- 대장암 / 염증성 장질환 / 셀리악병 가족력
- 빈혈, 발열, 만져지는 복부 덩어리

### B-2. 셀리악 검사 여부 확인 (필수) ⚠️

> **저포드맵을 시작하면 밀 섭취가 줄고, 글루텐을 줄인 상태에서는 셀리악 혈청검사가 위음성으로 나온다.**

앱이 사용자를 저포드맵으로 밀어넣는 순간, 그 사용자는 한동안 셀리악 진단 기회를 잃는다. 온보딩 필수 문구.

### B-3. 알레르기 등록 — 용량 로직 **우회**

| 구분 | 처리 |
|---|---|
| FODMAP 불내성 | 용량 조절 (역치 학습) |
| **IgE 알레르기** | **전량 배제. 용량 조언 금지.** 아나필락시스 위험이라 "조금은 괜찮다" 개념 자체가 성립하지 않음 |
| **셀리악병** | **전량 배제.** 미량에도 융모 손상 |

### B-4. 앱이 못 잡는 것 (인지하고 있을 것)

- 담즙산 흡수장애 — IBS-D 진단자의 상당수가 실제론 이것. 약물 치료 대상
- 히스타민 불내성
- 췌장 외분비 기능부전
→ **식이 개입에 반응이 없으면 병원으로 안내하는 exit 경로**가 필요하다.

### B-5. 제한 단계에 오래 머물게 하지 않는다

저포드맵을 장기 유지하면 안 되는 이유:
1. **영양 불균형** — 과일·유제품·통곡물·콩류를 광범위하게 배제 → 칼슘·식이섬유·철분 부족
2. **장내세균 다양성 감소** — 프럭탄·GOS는 **프리바이오틱**(유익균의 먹이). 4주가량 제한 시 비피더스균 감소 보고

> 저포드맵은 아이러니하게도 **"장에 좋은 것을 일시적으로 끊는" 식단**이다.

**제한 단계는 2~6주로 못 박고, 앱이 사용자를 여기 오래 머물게 하면 해를 끼치는 앱이 된다.**

### B-6. 게임화 금지 구역

"오늘 FODMAP 0점 달성!" 같은 **제한 자체를 보상하는 설계는 섭식장애 위험군에게 해롭다.**
보상은 "더 많이 피했다"가 아니라 **"더 많이 먹을 수 있게 됐다"**에 걸어야 한다.

## C. 핵심 도메인 모델

### C-1. 아형이 1차 분기

| 아형 | 정의 (비정상 배변일 기준, 브리스톨 척도) |
|---|---|
| IBS-C | 1~2형 >25%, 6~7형 <25% |
| IBS-D | 6~7형 >25%, 1~2형 <25% |
| IBS-M | 둘 다 >25% |
| IBS-U | 미분류 |

**같은 음식이 아형에 따라 정반대 조언이 된다.**
예: 자두/소르비톨 → IBS-C에는 완화 효과, IBS-D에는 악화.
→ "IBS에 나쁜 음식" 단일 목록은 존재할 수 없다.

### C-2. 역치 모델 + 스태킹

```
                    ┌──────── 통증 역치 ────────┐
[고포드맵 식사한 날]
  장내 가스·수분 ████████████        ← 바닥이 높음
  + 스트레스     ████████████▓▓▓▓  ← 넘음 😖

[저포드맵 식사한 날]
  장내 가스·수분 ████                ← 바닥이 낮음
  + 스트레스     ████▓▓▓▓            ← 안 넘음 😌
```

**"왜 같은 양파가 어떤 날은 괜찮은가"의 답:** 증상은 그 음식 하나가 아니라 **그 시점의 총 부하**가 결정한다.

부하 구성 요소: 당일 누적 FODMAP(**스태킹**) + 비FODMAP 트리거(지방·카페인·알코올·매운맛·탄산) + 스트레스 + 수면 + 생리 주기 + 최근 항생제/감염

### C-3. 민감도 계수는 동적이다

```
❌ user.fructan_threshold = 3.2g              (정적)
✅ threshold(user, date) = f(base, sleep[-1], condition[-1], cycle_phase, ...)
```

계수를 올리는 것: 스트레스↑, 수면 부족, 최근 장염(**감염 후 IBS**), 생리 주기
→ 초기에 정적 역치로 시작해도 되지만, **스키마는 처음부터 시계열을 전제로** 설계할 것.

### C-4. lag — 이 앱에서 가장 중요한 도메인 지식

```
식사
 ├─ 0~2h    위 배출
 │          ↳ 락토스·과당·폴리올: 소장 삼투 작용 → 이른 증상
 ├─ 4~8h    대장 도달 → 발효 → 가스
 │          ↳ 프럭탄·GOS: 여기서부터
 └─ 10~50h+ 대장 통과 (IBS-D 빠름 / IBS-C 며칠)
```

- **최소 24시간, 실무적으로 48시간** 창을 본다
- **FODMAP 그룹마다 lag가 다르다.** 단일 지연값 금지
- **아형마다 창 길이가 달라야 한다** (IBS-C는 더 길게)
- **lag는 학습시키지 말고 생리학적으로 고정한다.** 자유도를 주면 뭐든 유의하게 나와 과적합된다

> **lag를 잘못 잡으면 진범이 표에 아예 안 들어온다.** 코드가 아니라 생리학이 결정하는 파라미터.

### C-5. 통증의 4가지 경로 → 증상 로깅 분리

| 경로 | 통증 성격 | 시사 |
|---|---|---|
| 기계적 팽창 (가스·수분) | 빵빵한 압박, **팽만** | FODMAP 부하 |
| 평활근 경련 | **쥐어짜는 크램프** | 운동 이상, CRF |
| 화학적 자극 (담즙산·히스타민·프로테아제) | 화끈거림, **급박감** | 담즙산 흡수장애 등 |
| 중추 증폭 | 위 전부를 증폭 | 민감도 계수 |

→ **"복통" 단일 항목으로 로깅하면 안 된다.** 최소 팽만 / 크램프 / 급박감을 분리해야 트리거 역추적이 가능하다.

**참고:** IBS 환자와 정상인의 **장내 가스 총량은 크게 다르지 않다.** 차이는 분포와 지각이다. 저녁에 배가 실제로 나오는 현상은 가스량이 아니라 복부-횡격막 협조 이상 때문.

## D. 데이터 수집 설계

### D-1. 주관 > 객관 (근거 기반 결정)

**액티그래피(객관적 수면 지표)는 다음날 복통을 예측하지 못했고, 주관적 수면 질은 예측했다.** 2014년·2024년 연구 모두 동일 결과.

```
❌ 스마트워치 수면 데이터 연동에 리소스 투입
✅ "어젯밤 잘 주무셨나요? (1~5)" 슬라이더 하나
```

**MVP에서 웨어러블을 빼도 되는 근거이자, 빼는 게 나은 근거.**
이유: IBS는 지각의 병이므로, 예측 대상이 "지각된 통증"이면 예측 변수도 지각 쪽이 강하다.

### D-2. 측정 시각 분리 (동시 측정 편향 방어) ⚠️

```
❌ 20:00 배가 아픔 → 20:05 "통증 8/10, 스트레스 8/10" 동시 기록
   → 아프니까 스트레스도 높게 답함 → 가짜 상관 → 인과 추론 불가

✅ 아침 08:00  "어젯밤 수면?" + "지금 컨디션?"   ← 예측 변수
   증상 발생 시  통증 기록                        ← 결과 변수
```

**예측 변수는 항상 결과보다 시간적으로 선행해야 한다** (lag 원칙과 동일).

### D-3. 변수는 늘리는 게 아니라 줄인다

```
FODMAP 6 + 수면 + 스트레스 + 피로 + 생리주기 + 지방 + 카페인 + 알코올 = 14개
                                              → 필요 관측일 400일+ 😱
```

- 수면·스트레스·피로는 서로 강하게 상관됨 (다중공선성) → 모델이 구분해내지 못함
- **MVP 로깅 항목: 수면 질 + 컨디션, 2개만**
- 수면이 독립 슬롯을 받는 이유: **다음날 증상 예측력이 논문으로 입증된 유일한 변수**이기 때문

### D-4. 교란변수를 기록하지 않으면 인과 추론이 원천 불가

```
    스트레스 ────┐
        │        │
        ▼        ▼
      야식     복통     ← 둘 다 스트레스의 결과일 뿐, 서로 인과가 아닐 수 있음
```

100만 건이 쌓여도 스트레스를 함께 기록하지 않으면 구분 불가.
필요한 것: **교란변수 로그 + "스트레스가 낮은 날에도 야식을 먹은 관측"** (교란변수를 고정한 비교).

### D-5. 유효 표본 = 로그 수가 아니라 **노출의 변동량**

매일 똑같이 먹는 사용자는 1000건이 쌓여도 학습 불가. 프럭탄 섭취가 항상 3g이면 역치가 2g인지 5g인지 알 방법이 없다.

## E. 모델링 전략

### E-1. 개인별 ML은 사실상 도달 불가능

```
예측 변수 10~12개 × 변수당 유효 관측 10~20건
= 증상 있는 날 120~240건 필요
증상 발생률 40% 가정 → 300~600일
```

여기에 리텐션 벽이 겹친다. **건강 앱에서 3개월 넘게 매일 로깅하는 사용자는 통상 한 자릿수 %.**
→ "1년 쓰면 정확해집니다"는 제품으로 성립하지 않는다. **1주일 안에 가치를 줘야 한다.**

### E-2. 해법: 재도입 챌린지 = N-of-1 실험 설계 ⭐

| 관찰 데이터 | 설계된 챌린지 |
|---|---|
| 사용자가 먹은 걸 기록 | 앱이 용량을 지정 |
| 노출량이 우연에 의존 | 1일차 소량 → 2일차 중간 → 3일차 다량 |
| 교란변수 통제 안 됨 | 다른 FODMAP은 제거 상태로 고정 |
| 정보량 낮음 | **정보량 매우 높음** |

**한 그룹당 3일 계단식 챌린지 하나가 관찰 데이터 몇 주치보다 역치를 정확하게 잡는다.**

**챌린지 금지 조건:**
1. 알레르기/셀리악 대상 식품 (안전)
2. 스트레스·컨디션이 나쁜 날 (교란변수가 높으면 결과 해석 불가)
3. 다른 FODMAP이 이미 누적된 날 (스태킹 때문에 단일 그룹 귀인 불가)

### E-3. 3단계 로드맵

| 시점 | 데이터 | 방법 | 사용자가 받는 것 |
|---|---|---|---|
| 1일차 | 0건 | 집단 사전분포 + 규칙 기반 | FODMAP 계산기 |
| 2~6주 | 제거기 | baseline 확립 | 증상 감소 확인 |
| **6~16주** | **챌린지** | 계단식 용량 시험 | **그룹별 개인 역치** ← 핵심 산출물 |
| 3~6개월 | 200~400건 | **계층적 베이지안** | 역치 동적 보정, 신뢰구간 축소 |
| 1년+ | 500~1000건 | 개인 전용 ML | 도달자 극소수 |

### E-4. 계층적 베이지안 / partial pooling이 핵심

- 개인 역치를 0에서 학습하지 않고, **전체 사용자 분포를 사전(prior)으로 두고 개인 데이터로 끌어당긴다**
- 데이터가 적을 땐 집단 평균에 가깝고, 쌓일수록 개인화됨 → **콜드스타트 해결**
- **불확실성을 함께 산출**할 수 있음: "프럭탄 역치 3.2g (신뢰구간 1.8~5.5g)" → 앱이 과신하지 않게 됨

### E-5. 능동 학습 (active learning) — 차별화 기능

> "당신의 폴리올 역치는 2~6g으로 추정됩니다. 범위가 넓네요.
> 내일 점심에 아보카도 반 개(약 4g)를 드셔보시겠어요?"

사용자에겐 "제안", 뒤에서는 **정보 이득이 최대인 실험점 선택**. 데이터 희소성에 대한 가장 우아한 해법이고 기존 앱들이 안 하는 일.

### E-6. 데이터 함정 5종

| 함정 | 내용 |
|---|---|
| 데이터 희소성 | 개인당 하루 3~5끼. 한 달 써도 100건 남짓 |
| 콜드스타트 | 신규 사용자 데이터 0 → E-4로 해결 |
| 교란 | D-4 참조 |
| 지연 자유도 | lag를 자유롭게 고르면 뭐든 유의 → C-4로 고정 |
| **비무작위 결측** | 아픈 날엔 로깅을 안 함. **결측 자체가 증상과 상관** |

### E-7. 평균으로의 회귀 ⚠️

**IBS는 자연 경과로 좋아졌다 나빠졌다 한다. 사람들은 가장 심할 때 앱을 깐다.**
3개월 뒤 좋아진 건 앱 덕분이 아니라 그냥 파도의 골에서 마루로 간 것일 수 있다.

→ 대조군 없이 "우리 앱 쓰면 역치가 2.5배 올라갑니다"라고 마케팅하면 나중에 크게 데인다.

**역치 상승의 가능한 원인 4가지:** ①민감도 계수 감소(수면·스트레스 개선) ②측정 정확도 개선(초기 추정이 틀렸던 것) ③실제 생리적 적응(장내세균) ④**평균으로의 회귀**

## F. UX / 톤

### F-1. 화면 후보

| 화면 | 용도 |
|---|---|
| **오늘 남은 여유분** | 지금 뭘 먹을지 정하는 화면. 칼로리 앱 유사 |
| **역치 프로필 (6축)** | 나를 알아가는 화면. 시간에 따른 변화 표시 → 성장 서사 |

**역치는 단일 숫자가 아니다.** FODMAP 그룹별로 다르며(락토스는 멀쩡한데 폴리올만 약한 사람이 흔함), 화면은 6개 축의 프로필이어야 한다.

### F-2. 금지 문구 ⚠️

- ❌ "예민하신 거예요"
- ❌ "심리적 요인입니다"
- ❌ "실제로는 문제없습니다"

**근거:** 증상 중증도는 내장 과민성을 예측했지만 **심리적 특성은 예측하지 못했다.** 내장 과민성은 정신병리의 부산물이 아니라 독립적 생리 현상이다. 위 문구들은 근거에도 반하고 사용자를 소외시킨다.

**올바른 비유 (화재경보기):**
> 담배 연기에도 울리는 화재경보기. **연기도 진짜, 경보도 진짜다.** 다만 임계값이 낮게 설정되어 있을 뿐.
> "고장 나서 아무것도 없는데 울린다"가 아니다.

### F-3. 앱의 킬러 메시지

> **"당신 생각과 달리, 범인은 8시간 전 점심입니다."**

사용자는 십중팔구 직전에 먹은 것을 범인으로 지목한다. 자가 귀인이 틀리기 때문에 사람들이 혼자서는 트리거를 못 찾는다. 이 직관을 데이터로 뒤집는 것이 핵심 가치.
